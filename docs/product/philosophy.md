# Product Philosophy

## Why

Product philosophy gives future features a consistent set of decision filters.

## What

A feature belongs in Ascend only when it can answer these questions well:

1. **Does it reduce cognitive load?**
2. **Does it preserve human agency?**
3. **Does it earn recurring attention rather than assume it?**
4. **Does it explain itself at the moment it matters?**
5. **Would someone genuinely want to return tomorrow?**

If a feature cannot answer these questions, it should be simplified, deferred, or declined.

## How

Use these filters during discovery, requirements, design review, and release review. Use the [constitution](../vision/constitution.md) for non-negotiable boundaries and the [principles](../vision/principles.md) for the detailed review checklist.

## Future Considerations

Add evidence expectations for each filter only after the MVP outcome is approved.
