# Documentation workflow

1. Start with the user outcome and constraints.
2. Update the relevant product or architecture document before implementation when the decision is material.
3. Record durable technical decisions as ADRs using the [template](../decisions/adr-template.md).
4. Link implementation work to the decision it realizes.
5. Revise stale documentation in the same pull request as the behavior change.

An ADR records a decision, not every discussion. Small implementation details belong close to the code unless they create a lasting constraint.
